# 总体架构与子链组织

文档版本：v1。状态：设计规范，待实现与验收。

[总览](../README.md) · [公共契约](contracts.md)

子链以稳定外部契约完成业务任务；内部流程及可替换实现服务于快速、准确地产生该产物。以下模块和目录属于后续代码组织设计，本轮仅建立文档。

## 1. 文档权责与稳定边界

| 文档 | 负责内容 | 使用者 |
|---|---|---|
| [README.md](../README.md) | 目标、十个业务子链、导航与运行目录约定 | 用户、主调度和总体设计审阅 |
| [contracts.md](contracts.md) | 公共外壳、类型、准确引用、状态与强校验 | 全部子链及独立验证者 |
| docs/chains/子链/README.md | 该子链的问题、外部输入输出、科学方法和验收 | 主链、上下游、独立验证者 |
| docs/chains/子链/internal.md | 私有步骤、内部约定、编排、转换和扩展 | 子链内部实现者 |

同一业务定义保留一个权威位置，其他文档通过链接引用。内部接口只是实现手段，不能成为主链新增业务输入的理由，也不能要求下游理解某个网站的字段或某个分析器的私有结果。

外部稳定性同时包含结构、字段含义、单位、时间口径、精度、范围、错误与降级语义。更换适配器或内部步骤可以改变取得的材料和实际计算结果，仍须履行同一外部契约并记录真实方法版本。内部改动若要求改变这些业务含义，属于外部协议变更，不能作为兼容扩展静默上线。

## 2. 子链模块组织

每条子链按独立包组织，包内模块数量取决于实际复杂度；启动脚本只负责参数解析和调用统一入口。主链调用子链入口，不直接调用适配器、分析器或内部步骤。

建议后续代码布局：

~~~text
src/investment/
  runtime/
    controller.py       主链顺序、准确引用、权限、独立验收和封存
    context.py          数据访问、时钟、取消、预算及记录能力
  contracts/            公共外部 schema 和类型
  storage/              原始证据、产物与执行记录
  chains/
    news_collection/
      chain.py          唯一业务入口，外部输入到候选输出
      contracts/        子链外部输入、输出和表 schema
      validation.py     由调度者独立调用的阶段验证者
      internal/
        workflow.py     私有流程编排
        types.py        私有步骤及采集结果约定
        providers/      同采集能力的不同网站实现
        normalize.py    原始数据到标准内部记录
        assemble.py     形成外部 EvidenceCorpus
    fund_universe/
      chain.py
      contracts/
      validation.py
      internal/
        workflow.py
        providers/      主动目录/同类列表发现、身份与披露取材
        analyzers/      身份、暴露和同类范围分析
        assemble.py
    其余子链按同一外部边界组织，按需要增加内部模块
~~~

上述是模块职责设计，不要求每条子链都创建全部模板目录；单步骤可以先是一个内部模块。并行、恢复与缓存也按该子链任务需要实现。

阶段验证者可以与子链位于同一个代码包，但其调用、规则身份和验收权限由主调度控制。文件位置不构成验证独立性；生产者及内部插件都不能自签许可。

箭头代表业务依赖，不代表把全部上游数据无差别复制到下一阶段。每个子链只接收其输入契约列出的准确引用。账户、范围、方法、数据与合同的版本都由调度者绑定。

调度者承担：

1. 创建 run_id，记录真实时钟，绑定准确账户版本和初始任务。
2. 在每次执行前校验输入 schema、引用和该子链的使用许可。
3. 执行子链，取得候选产物，再调用与生产者分离的验证器。
4. 验证通过后封存产物与验收凭证，再允许下游消费；生产者不能自行写 passed 获得资格。
5. 保存阶段状态、失败边界、已用预算及完整缺口。同一任务恢复沿用冻结输入与记录，不通过重试清除已知失败或重复检验次数。
6. 按权限隔离独立验证资料。SC06、SC07 不得读取独立验证的未来结果；仅声明某文件为 test 不足以建立隔离。
7. 相关事实变更产生新版本，使受影响下游结果失效。不中途用新账户、最新价格或新费用替换旧链的输入。
8. 冻结 goal_rule_ref，逐链维持原始发现名单、取材处置和实际比较的绑定。SC04 主动发现原列表，SC05 主动取材；可选复用资料不能变成调用者必填的原始事实。
9. 正常报告路径在 SC10 封存后调用独立根目标验证者汇总十链与原证据，取得 GoalEvidence，返回 ResearchResult。无有效报告封存的等待/失败路径，仍由根验证者读取已完成前缀及控制记录返回 pending/unmet，未取得的账户与报告引用保持 unknown，不能 achieved。必要事实或可继续工作对应 pending，本次完整目标已判定不能完成时对应 unmet；不自行把阶段完成、交付成功写成 achieved。

标准交接：

~~~text
输入结构校验
→ 引用、范围、来源及时间校验
→ 业务前置条件校验
→ 执行并生成候选输出
→ 输出结构与语义校验
→ 独立阶段验收
→ 封存输出及验收凭证
→ 下游按用途消费
~~~

根结果由调度汇总；完整目标的通过须在有效 SC10 封存后，尚无有效报告的控制分支只返回 pending/unmet。SC10 内容预核对、实际交付及最终验收的时序见 [报告内部流程](chains/reporting/internal.md)。ReportBundle 不引用尚未生成的根证据；ResearchResult 再引用 GoalEvidence 和已封存报告。观察分支仍可交付报告，但不自动满足完整目标。

### 3.1 原始名单到实际比较的证据流

~~~text
冻结本次渠道/产品域/同类规则与目标
→ SC04 主动搜索目录/同类列表，保留原字节、分页和未知范围
→ 冻结原始发现名单 U，独立核实闭合及 C/E/K 分区
→ SC05 对 U、实际风险及必要行业资料逐项取材/处置
→ SC06 保留每个成员的预测就绪/不适用/未知状态
→ SC07 依据冻结规则确定应比较集合 R，记录真实计算集合 A
→ SC08 独立复核原列表、处置、R 的依据、A = R 及科学金融资格
→ SC09 沿用获准动作并核对发布前提
→ SC10 展示原名单、逐项处置、实际比较及限制，独立内容验收
→ 根目标验收与 ResearchResult
~~~

U 的集合分区、自哈希、来源任务完成、预测就绪和方案求解是不同证明责任。不能将已下载或可运行的子集当 U，也不能将计划比较的成员当 A。R 外成员须有原证据支持的排除或独立非重大影响证明，未知及未比较项保留；未知分页使列表完整性未证实。费用、模型及比较资格分别验收，保持全部真实风险对象。

工程预算只限制一次工作的规模。基金任务不得通过 top N、手选集合、下载成功或预算耗尽改变原同类分母；可分批和并发执行，未完成项保留 Gap。金额精度及合法动作约束可以限制政策集合，但不能据此偷偷删基金。有限比较只能说明实际范围，不能取得完整同类目标或跨范围最优资格。

## 4. 内部流程与私有约定

子链统一负责把稳定业务输入变成所需内部任务，再把内部结果转换成稳定业务输出：

~~~text
外部 StageInput
→ 解析准确输入并形成私有执行计划
→ 选择兼容内部实现、冻结版本和配置
→ 调用内部步骤、适配器、分析器或计算器
→ 校验私有结果，进行单位/时点对齐和冲突处理
→ 汇总业务材料、证据、尝试记录与 Gap
→ 对照该子链外部契约组装 CandidateOutput
→ 交主调度独立验收与封存
~~~

私有执行计划描述步骤依赖、输入引用、所选实现、配置、预算和恢复键。步骤只读取计划授权的输入；缺跨子链上游产物时回交主调度，不能自行挑选 latest 或越过其他子链的验收。

私有步骤结果需要区分成功、部分结果、业务未就绪、执行失败和取消，并携带准确材料引用及原因。名称和具体类型由子链内部定义，不能直接附加到外部产物。内部计划中的完成状态也不能冒充外部 ValidationReceipt 的资格。

错误在责任步骤处理：网站超时可以形成尝试记录和 Gap；格式或单位无法确定时拒绝对应材料；程序错误记录失败，不能降级为成功的空结果。候选产物能否形成由子链外部契约决定，不能为了统一返回结构补造必需字段。

## 5. 可扩展实现、并发与恢复

### 5.1 扩展按业务能力定义

| 内部组件 | 负责内容 | 不承担的权力 |
|---|---|---|
| Provider/适配器 | 从不同来源取得同能力的原始材料及获取记录 | 不证明材料真伪，不授予决策许可 |
| Analyzer/分析器 | 以确定方法完成身份、暴露、机制或同类诊断 | 不把任意评分解释为收益概率 |
| Forecaster/预测实现 | 在已授权资料和协议下产生同目标的预测 | 不读取封存测试结果来择优 |
| Solver/决策计算器 | 在同目标、约束和口径下求解声明动作集合 | 不改变资金事实、风险预算或比较分母 |
| Renderer/呈现器 | 把封存结果转换成报告视图 | 不改变金额、排名或资格 |

同能力的多个实现使用共同私有接口及结果约定。例如新闻按配置的来源域选择兼容网站适配器，同时采集多个网站，统一产生可规范化原文；新闻不要求全球发现。基金同类列表主动搜索后取材，净值、费用、身份和披露持仓是不同能力，不强行合并成万能抓取结果。收益预测与暴露分析也不共享一个任意 score。

私有注册表记录实现身份、能力、版本、输入/输出类型版本、支持范围和配置。子链根据业务输入选择已注册、已授权的实现；调用者不需要知道内部类名或步骤名称。每次运行冻结实际选择并写入方法/执行记录，使用外部既有 method_ref、evidence_refs 等引用传递追溯依据。

新增同能力实现通常只需新增适配器或分析器、登记兼容范围并验证其映射；主链及子链外部输入输出保持不变。私有接口可以独立演进，版本转换由子链内部负责。

### 5.2 并行、汇总与失败隔离

独立来源任务可以在子链内部并发，按站点和全局预算限制速率、连接数、超时与重试；共享身份、资金或需要前序结果的步骤按依赖执行。并发是效率措施，不作为覆盖或科学资格依据。

每个任务单独记录成功、失败、取消及未执行项。一个来源失败不抹去其他有效材料；其他来源成功也不能填补失败来源的未覆盖范围。汇总保留重复来源、转载关系、冲突证据和未知，不按完成先后决定可信度，不直接平均不兼容值。

内部结果先规范化再组装外部产物；来自不同网站的单位、币种、经济期间、原文版本及可得时间必须明确。已取原文但解析失败时，保留尝试证据和 Gap，不将缺必需正文引用的记录冒充完整文档。

并行模型或策略搜索还须服从冻结候选空间、评价规则、搜索预算及完整尝试记录。仅训练/选择资料可共享；独立测试权限保持隔离，赢家冻结后再评价，不能由多个内部实现反复试同一测试集来挑赢家。

### 5.3 复用及恢复

可复用结果绑定准确输入、实现及配置版本、原始来源版本、时间/范围与许可。当前来源变化、版本改变或有效期失效时重新取得或重新验证；缓存命中不构成事实仍有效的证据。

恢复先核对冻结计划、已完成记录及允许用途，复用可核步骤结果，继续未完成任务。保留中断、失败、实际尝试预算和独立检验历史。最终产物按登记的稳定排序或主键形成，不能由并发完成顺序改变内容含义。

## 6. 参数、证据边界与变更规则

### 6.1 参数来源

| 来源 | 例子 | 确定时点 |
|---|---|---|
| 用户确认 | 本金损失容忍、资金需求、期限、渠道限制 | 账户/偏好生效时；改变后更新版本 |
| 原始合同 | 费率、份额精度、最低额、锁定、确认和到账 | 来源核验与合同适用期 |
| 训练或选择资料 | 模型参数、特征、允许学习的情景方法参数 | 对应训练/选择阶段，按预登记规则 |
| 预登记统计协议 | 指标、置信水平、经济门槛、区间方法、重复检验处理 | 独立验证结果开放前 |
| 工程预算 | 采集分页、搜索时间、重试次数 | 运行前；只限制工作，不授予覆盖或资格 |

不能随意把固定新闻天数、样本量、风险分位、模型窗口或置信水平写成科学常数。必要参数没有依据时，该方法为未就绪；先保留缺口，不用默认值制造科学资格。本金损失、终点风险、路径回撤和流动性分别登记，不能隐式转换成同一种约束。

### 6.2 证据能支持的结论

| 已取得的证据 | 可以支持 | 仍需另行证明 |
|---|---|---|
| 原文字节及来源 | 某版本材料已取得 | 内容真实、机制正确、市场未定价 |
| 交叉核实事实 | 已登记事实规则被满足 | 因果效应或投资收益 |
| 行业机制及暴露 | 存在可研究联系 | 可预测收益和合格金额 |
| 历史时点合格数据 | 输入在登记 origin 可用 | 模型泛化和交易效果 |
| 独立历史模拟 | 在注明范围与假设下的样本外结果 | 真实交易实现与未来保证 |
| 前瞻或真实成交记录 | 已成熟期间的对应表现 | 未来持续有效 |
| 结构、守恒和重算检查 | 对应工程与金融合同通过 | 模型假设及市场有效性 |

### 6.3 版本与恢复

源材料、用户事实、范围、方法、数据、模型和决策的变更都产生新版本，并显式关联 supersedes_ref 或新试验身份。只重新运行受影响下游，但必须重新核对全部必要前提。

同任务恢复只复用输入一致、引用可核、许可仍有效的封存结果。账户或风险变更要求新决策；新 ID 不抹除同方法族已用的独立检验记录。纯报告表达修正可以只重做 SC10，改变经济含义时返回相应责任阶段。

## 7. 文档与后续实现验收

本文的十个子链都已定义职责和输入输出。SC01已有封闭Schema、独立验证器与运行实现；SC02—SC10仍须补齐对应JSON Schema、表schema及业务验证器后启用，职责文档本身不代表实现或强校验通过。

验收至少覆盖：

1. 必填字段缺失、未知字段、错误类型、非有限数值、单位/币种或时间精度错误被拒绝。
2. 引用哈希、上游身份、账户版本及候选范围不一致被拒绝。
3. null、零、空数组和不适用状态保持不同含义，必要未知阻断依赖用途。
4. 修订后历史数据、未成熟标签、训练外拟合或独立验证泄漏不得取得相关许可。
5. 金融核算拒绝双重计入、未知费率填零、未到账资金支持申购及非法精度动作。
6. 方案选择冻结完整规则；独立验证不得调参、重选或改变门槛。
7. 求解最优、统计资格、风险恢复、发布许可、报告交付和实际投资结果分别表达。
8. 账户/合同时效变化阻断旧建议；报告金额、排名、资格和范围与准确输入一致。

SC02—SC10目前仅形成设计文档。运行时代码、schema 文件、真实数据适配、模型效果和真实宿主调用须在后续明确的实施范围内单独验证。

### 7.1 本次文档修复的静态场景验收

本表检查文档要求是否形成闭合责任链，不表示程序已经执行这些场景。

| 场景 | 文档规定的结果与核对责任 |
|---|---|
| 新闻只配置若干站点，其中一个不支持解析 | SC02 保留配置域、成功原文、失败尝试和未知覆盖，不扩大范围；SC10 如实展示 |
| 同类目录有多页，预算只够抓前几页 | SC04 保存分页关系和未处理范围，闭合未知；不能以已抓数为分母认证完整 |
| 原同类成员已发现，但 NAV、费率或身份资料不足 | SC04/05 保留原成员及 unknown/Gap；不能因缺资料归为有据排除 |
| 已发现全部成员，只有部分具备可运行模型 | SC06 保留逐成员处置，SC07 真实记录 R/A 和未比较；不能直接把就绪子集视为完整 |
| 原列表、来源审计均完成，但计算遗漏应比较成员 | SC08 从原证据复核 A 与 R，不授予完整比较资格；根目标不能 achieved |
| 部分成员有客观不适用证据或未知有独立非重大影响证明 | 保留完整 U 和逐项证明，由 SC08/根验证者核实 R 的合理性；不凭 producer 标记放行 |
| 有完整证据支持当前保持/不操作 | SC07/08/09 仍通过必要比较、风险和发布检查；无动作不意味着跳过研究 |
| 观察报告交付成功 | SC10 可记录 delivered；本次完整目标已判定不能完成时为 unmet，仍有可继续工作时为 pending；不将交付等同科学通过 |
| 完整研究和报告内容已独立通过，真实交付失败 | SC10 记录 delivery_failed；独立根证据可为 achieved，实际交付待办仍保留 |
| 必要用户事实或本次可继续的来源/分析尚未完成 | 根读取已完成前缀和控制记录返回 pending，未取得账户/报告引用为 unknown；只等待未来标签或真实收益则当前目标 unmet |
| 报告预核对或最终验收发现金额、名单或资格错配 | 内容不能通过；预核对失败不交付，最终失败保留已发生事实，根不能 achieved |
| 当前截点或历史初始账户协议未确定 | 阻断依赖该决定的资格，不用默认映射或今日账户制造历史证明 |

### SC01 数据与运行边界

SC01的data仅两张表：trades按(account_id,trade_id)保存当前必要整笔交易；ledger_meta按账户保存当前范围、真实用户事实时点、generation/digest及最新提交marker。没有逐日完整账户、源记录、候选或验收凭证归档表。业务事实变化才增加generation；系统每轮控制身份及finalize不增加业务版本。

SC01运行源输入、真实SQLite冻结基线、方法、派生Context/持仓/pending与验收产物在runs/sc01/YYYYMMDD/invocation_id。下游消费准确冻结引用，不能读latest替换。未finalized提交先恢复且禁止覆盖；清理只处理无未完成/有效使用的运行文件，不删除交易。默认目录和日期README统一见插件README，强格式见spec/v1。
