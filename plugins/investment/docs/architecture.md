# 总体架构与子链组织

文档版本：v1。状态：架构设计规范；实现进度见项目总览，规范本身不代表程序已通过验证。

[总览](../README.md) · [公共契约](contracts.md)

开发顺序、三类脚本职责、审查方法及单测准入先遵守 [项目约束](../AGENTS.md)。本页规定业务组织和调度边界，不另设缓存复用或局部重跑来替代本轮完整链路。

子链以稳定外部契约完成业务任务；内部流程及可替换实现服务于快速、准确地产生该产物。以下模块和目录用于说明职责组织，不要求已实现部分采用所有示意目录，也不以本文修订证明实现已经完成。

## 2. 子链模块组织

每条子链按独立包组织，包内模块数量取决于实际复杂度；启动脚本只负责参数解析和调用统一入口。主链调用子链入口，不直接调用适配器、分析器或内部步骤。

当前实现位置如下；子链目录使用业务名称，链号用于外部身份，各自映射在子链说明中固定列出。

| 子链 | 说明目录 | 实际代码包 | 精确规范 |
|---|---|---|---|
| SC01 | [account](chains/account/README.md) | [src/investment/chains/account](../src/investment/chains/account/) | [SC01 v1](spec/v1/sc01.md) |
| SC02 | [news_collection](chains/news_collection/README.md) | [src/investment/chains/news](../src/investment/chains/news/) | [SC02 v1](spec/v1/sc02.md) |
| SC03—SC10 | 各自 chains 目录 | 尚未实现 | 本链专用机器规范待定义 |

后续子链的职责布局示意（不作为当前文件清单）：

~~~text
src/investment/
  runtime/
    controller.py       主链顺序、准确引用、权限、独立验收和封存

  contracts/            公共外部 schema 和类型
  storage/              必要业务数据持久化；临时证据与产物存运行目录
  chains/
    news_collection/
      chain.py          唯一业务入口，外部输入到候选输出
      contracts/        子链外部输入、输出和表 schema
      validation.py     由调度者独立调用的阶段验证者
      internal/
        workflow.py     私有流程编排
        types.py        私有步骤及采集结果约定
        providers/      同采集能力的不同网站实现
        normalize.py    原始数据到标准内部记录
        assemble.py     形成外部 EvidenceCorpus
    fund_universe/
      chain.py
      contracts/
      validation.py
      internal/
        workflow.py
        providers/      主动目录/同类列表发现、身份与披露取材
~~~

上述是模块职责设计，不要求每条子链都创建全部模板目录；单步骤可以先是一个内部模块。内部并发或已确认的提交状态处理按实际需要定义，不以工程模板新增业务场景。

阶段验证者可以与子链位于同一个代码包，但其调用、规则身份和验收权限由主调度控制。文件位置不构成验证独立性；生产者及内部插件都不能自签许可。

## 3. 总链路与调度责任

~~~mermaid
flowchart TD
    REQUEST[任务材料：交易、分析资金与用户约束] --> A[SC01 基金交易记录]
    REQUEST --> B[SC02 原文采集]
    A -->|基金与未完成交易对象| B
    B --> C[SC03 事实与经济假说]
    A --> D[SC04 投资工具范围]
    C --> D
    C -->|行业及暴露观测| E
    D -->|原始名单及发现审计| E[SC05 金融取材与时点实验]
    A --> E
    E --> F[SC06 预测与联合情景]
    A -->|交易与登记持仓| G[SC07 方案选择并冻结]
    REQUEST -->|独立资金计划与用户约束| G
    REQUEST -->|目标与用户约束| E
    REQUEST -->|独立资金与约束| H
    REQUEST -->|发布时前提| I
    D -->|原同类分母| G
    E --> G
    F --> G
    G --> H[SC08 独立资格验证]
    A --> H
    F -->|冻结模型及更新规则| H
    E -->|获准的独立验证资料| H
    H --> I[SC09 建议与发布许可]
    G -->|已验证动作| I
    A --> I
    I --> J[SC10 报告交付]
    H -->|证据不足或未通过| J
    C -->|仅有观察结论| J
    J -->|SC10 内容验收与封存| ROOT[独立根目标验证 GoalEvidence]
    REQUEST -->|调度记录的等待或失败| CONTROL[已完成阶段前缀及控制记录]
    CONTROL -->|无有效报告时 pending 或 unmet| ROOT
    ROOT --> RESULT[ResearchResult 与 goal_status]
    RESULT --> USER[用户实际操作及真实反馈]
    USER --> NEXT[新账户版本与下一次研究]
~~~

箭头代表业务依赖，不代表把全部上游数据无差别复制到下一阶段。每个子链只接收其输入契约列出的准确引用。账户、范围、方法、数据与合同的版本都由调度者绑定。

调度者承担：

1. 创建 run_id，记录真实时钟，绑定准确账户版本和初始任务。
2. 把上一子链已验证的本轮输出按契约交给下游；入口负责必要字段和运行边界检查，不重新执行上游业务验证。
3. 调用流程脚本取得候选，再调用与生产者分离的验证脚本，核对当前输出的合理性、有效性及事实依据。
4. 验证通过后封存产物与验收凭证，再允许下游消费；生产者不能自行写 passed 获得资格。
5. 保存阶段状态、失败边界、已用预算及完整缺口。同一任务恢复沿用冻结输入与记录，不通过重试清除已知失败或重复检验次数。
6. 按权限隔离独立验证资料。SC06、SC07 不得读取独立验证的未来结果；仅声明某文件为 test 不足以建立隔离。
7. 本轮输入事实、方法和判断时点在重试中保持不变；确需更新事实时回到对应责任方，形成新的合法任务输入，不擅自改写本轮依据。
8. 冻结 goal_rule_ref，逐链维持原始发现名单、取材处置和实际比较的绑定。SC04 主动发现原列表，SC05 主动取材；可选复用资料不能变成调用者必填的原始事实。
9. 正常报告路径在 SC10 封存后调用独立根目标验证者汇总十链与原证据，取得 GoalEvidence，返回 ResearchResult。无有效报告封存的等待/失败路径，仍由根验证者读取已完成前缀及控制记录返回 pending/unmet，未取得的账户与报告引用保持 unknown，不能 achieved。必要事实或可继续工作对应 pending，本次完整目标已判定不能完成时对应 unmet；不自行把阶段完成、交付成功写成 achieved。

标准交接：

~~~text
入口必要字段与运行边界检查
→ 本轮上游已验证输出作为子链输入（第一子链由入口登记用户事实）
→ 流程脚本处理并生成候选输出
→ 验证脚本独立核对当前输出的合理性、有效性及事实依据
→ 封存输出及验收凭证
→ 下游按用途消费
~~~

根结果由调度汇总；完整目标的通过须在有效 SC10 封存后，尚无有效报告的控制分支只返回 pending/unmet。SC10 内容预核对、实际交付及最终验收的时序见 [报告内部流程](chains/reporting/internal.md)。ReportBundle 不引用尚未生成的根证据；ResearchResult 再引用 GoalEvidence 和已封存报告。观察分支仍可交付报告，但不自动满足完整目标。

### 3.1 原始名单到实际比较的证据流

~~~text
冻结本次渠道/产品域/同类规则与目标
→ SC04 主动搜索目录/同类列表，保留原字节、分页和未知范围
→ 冻结原始发现名单 U，独立核实闭合及 C/E/K 分区
→ SC05 对 U、实际风险及必要行业资料逐项取材/处置
→ SC06 保留每个成员的预测就绪/不适用/未知状态
→ SC07 依据冻结规则确定应比较集合 R，记录真实计算集合 A
→ SC08 独立复核原列表、处置、R 的依据、A = R 及科学金融资格
→ SC09 沿用获准动作并核对发布前提
→ SC10 展示原名单、逐项处置、实际比较及限制，独立内容验收
→ 根目标验收与 ResearchResult
~~~

U 的集合分区、自哈希、来源任务完成、预测就绪和方案求解是不同证明责任。不能将已下载或可运行的子集当 U，也不能将计划比较的成员当 A。R 外成员须有原证据支持的排除或独立非重大影响证明，未知及未比较项保留；未知分页使列表完整性未证实。费用、模型及比较资格分别验收，保持全部真实风险对象。

工程预算只限制一次工作的规模。基金任务不得通过 top N、手选集合、下载成功或预算耗尽改变原同类分母；可分批和并发执行，未完成项保留 Gap。金额精度及合法动作约束可以限制政策集合，但不能据此偷偷删基金。有限比较只能说明实际范围，不能取得完整同类目标或跨范围最优资格。

## 4. 内部流程与私有约定

子链统一负责把稳定业务输入变成所需内部任务，再把内部结果转换成稳定业务输出：

~~~text
外部 StageInput
→ 解析准确输入并形成私有执行计划
→ 选择兼容内部实现、冻结版本和配置
→ 调用内部步骤、适配器、分析器或计算器
→ 校验私有结果，进行单位/时点对齐和冲突处理
→ 汇总业务材料、证据、尝试记录与 Gap
→ 对照该子链外部契约组装 CandidateOutput
→ 交主调度独立验收与封存
~~~

私有执行计划描述步骤依赖、输入引用、所选实现、配置、预算和恢复键。步骤只读取计划授权的输入；缺跨子链上游产物时回交主调度，不能自行挑选 latest 或越过其他子链的验收。

私有步骤结果需要区分成功、部分结果、业务未就绪、执行失败和取消，并携带准确材料引用及原因。名称和具体类型由子链内部定义，不能直接附加到外部产物。内部计划中的完成状态也不能冒充外部 ValidationReceipt 的资格。

错误在责任步骤处理：网站超时可以形成尝试记录和 Gap；格式或单位无法确定时拒绝对应材料；程序错误记录失败，不能降级为成功的空结果。候选产物能否形成由子链外部契约决定，不能为了统一返回结构补造必需字段。

## 5. 可扩展实现、并发与恢复

### 5.1 扩展按业务能力定义

| 内部组件 | 负责内容 | 不承担的权力 |
|---|---|---|
| Provider/适配器 | 从不同来源取得同能力的原始材料及获取记录 | 不证明材料真伪，不授予决策许可 |
| Analyzer/分析器 | 以确定方法完成身份、暴露、机制或同类诊断 | 不把任意评分解释为收益概率 |
| Forecaster/预测实现 | 在已授权资料和协议下产生同目标的预测 | 不读取封存测试结果来择优 |
| Solver/决策计算器 | 在同目标、约束和口径下求解声明动作集合 | 不改变资金事实、风险预算或比较分母 |
| Renderer/呈现器 | 把封存结果转换成报告视图 | 不改变金额、排名或资格 |

同能力的多个实现使用共同私有接口及结果约定。例如新闻按配置的来源域选择兼容网站适配器，同时采集多个网站，统一产生可规范化原文；新闻不要求全球发现。基金同类列表主动搜索后取材，净值、费用、身份和披露持仓是不同能力，不强行合并成万能抓取结果。收益预测与暴露分析也不共享一个任意 score。

私有注册表记录实现身份、能力、版本、输入/输出类型版本、支持范围和配置。子链根据业务输入选择已注册、已授权的实现；调用者不需要知道内部类名或步骤名称。每次运行冻结实际选择并写入方法/执行记录，使用外部既有 method_ref、evidence_refs 等引用传递追溯依据。

新增同能力实现通常只需新增适配器或分析器、登记兼容范围并验证其映射；主链及子链外部输入输出保持不变。私有接口可以独立演进，版本转换由子链内部负责。

### 5.2 并行、汇总与失败隔离

独立来源任务可以在子链内部并发，按站点和全局预算限制速率、连接数、超时与重试；共享身份、资金或需要前序结果的步骤按依赖执行。并发是效率措施，不作为覆盖或科学资格依据。

每个任务单独记录成功、失败、取消及未执行项。一个来源失败不抹去其他有效材料；其他来源成功也不能填补失败来源的未覆盖范围。汇总保留重复来源、转载关系、冲突证据和未知，不按完成先后决定可信度，不直接平均不兼容值。

内部结果先规范化再组装外部产物；来自不同网站的单位、币种、经济期间、原文版本及可得时间必须明确。已取原文但解析失败时，保留尝试证据和 Gap，不将缺必需正文引用的记录冒充完整文档。

并行模型或策略搜索还须服从冻结候选空间、评价规则、搜索预算及完整尝试记录。仅训练/选择资料可共享；独立测试权限保持隔离，赢家冻结后再评价，不能由多个内部实现反复试同一测试集来挑赢家。

### 5.3 本轮执行与重处理

正常任务完整顺序执行总链路，各链验证通过后直接传递本轮实际输出。缓存结果、旧流程输出或既往验证结论不能替代本轮实际执行。必要历史业务记录是本轮合法上下文，不等于复用旧脚本输出。

验证失败携带结构化原因返回当前流程，首次加两次重试最多三次；冻结输入事实、方法及判断时点不变，耗尽后停止全部后续阶段。提交已经发生的操作按已定义提交状态处理，避免重复记账，不借恢复重置预算。最终产物按登记的稳定排序或主键形成，不能由内部并发完成顺序改变含义。

## 6. 参数、证据边界与变更规则

### 6.1 参数来源

| 来源 | 例子 | 确定时点 |
|---|---|---|
| 用户确认 | 本金损失容忍、资金需求、期限、渠道限制 | 账户/偏好生效时；改变后更新版本 |
| 原始合同 | 费率、份额精度、最低额、锁定、确认和到账 | 来源核验与合同适用期 |
| 训练或选择资料 | 模型参数、特征、允许学习的情景方法参数 | 对应训练/选择阶段，按预登记规则 |
| 预登记统计协议 | 指标、置信水平、经济门槛、区间方法、重复检验处理 | 独立验证结果开放前 |
| 工程预算 | 采集分页、搜索时间、重试次数 | 运行前；只限制工作，不授予覆盖或资格 |

不能随意把固定新闻天数、样本量、风险分位、模型窗口或置信水平写成科学常数。必要参数没有依据时，该方法为未就绪；先保留缺口，不用默认值制造科学资格。本金损失、终点风险、路径回撤和流动性分别登记，不能隐式转换成同一种约束。

### 6.2 证据能支持的结论

| 已取得的证据 | 可以支持 | 仍需另行证明 |
|---|---|---|
| 原文字节及来源 | 某版本材料已取得 | 内容真实、机制正确、市场未定价 |
| 交叉核实事实 | 已登记事实规则被满足 | 因果效应或投资收益 |
| 行业机制及暴露 | 存在可研究联系 | 可预测收益和合格金额 |
| 历史时点合格数据 | 输入在登记 origin 可用 | 模型泛化和交易效果 |
| 独立历史模拟 | 在注明范围与假设下的样本外结果 | 真实交易实现与未来保证 |
| 前瞻或真实成交记录 | 已成熟期间的对应表现 | 未来持续有效 |
| 结构、守恒和重算检查 | 对应工程与金融合同通过 | 模型假设及市场有效性 |

### 6.3 事实更新与本轮依据

源材料、用户事实、范围、方法、数据、模型和决策的真实更新须由相应责任方记录。新事实按既定契约形成新的任务输入；新任务仍执行完整链路，不能由当前流程自行改值或只重跑方便通过的阶段。

账户或风险变更要求以真实事实重新研究；新任务身份不抹除模型方法已用的独立检验记录。文档表达修订与实际研究执行分别报告，不能把局部文件编辑当作整链重新验证。

## 9. 数据与运行目录约定

本节是运行数据目录、每日 README 和生命周期的统一说明。开发与测试隔离遵守 [项目约束](../AGENTS.md#9-正式数据与单测数据隔离)；各子链的具体文件、命令与提交机制见其 internal，精确约束见对应 spec。

### 9.1. 根目录结构

~~~text
~/.investment/
├── data/
│   └── investment.sqlite              # 本地 SQLite 方案的文件示例
├── runs/
│   └── <子链标识>/
│       └── <执行日期YYYYMMDD>/
│           ├── manifest.json          # 当天调用与尝试状态的机器记录
│           ├── README.md              # 从 manifest 生成各次调用内容说明
│           ├── <invocation_id_1>/
│           └── <invocation_id_2>/
└── test/
    └── <test_run_id>/                  # 单测批次，不能作为正式运行根
        ├── data/investment.sqlite     # 本批模拟交易数据库
        ├── runs/<子链标识>/<YYYYMMDD>/...    # 本批输入、产物及校验结果
        └── verification-report.json   # 完整场景单测的汇总报告
~~~

- data 保存每天确有后续用途的必要业务数据。SC01 本地账户存储采用 SQLite，表结构和完整校验约束见 [数据库规范](spec/v1/sc01.md#必要数据存储)；其他子链数据尚不预建表。
- runs 保存本轮输入副本、中间结果、临时校验材料、日志和本次输出；按用途结束情况清理，不默认永久保存或逐份写入数据库。
- 子链标识用于区分业务子链，例如 sc01；invocation_id 对应公共 StageInput 的单次调用身份。不同调用使用不同目录，不覆盖其他调用的文件。
- YYYYMMDD 是执行日期，例如 20261014；使用统一登记的时区，当前为 Asia/Shanghai。同次执行跨日继续时沿用原执行目录。
- 账户事实时点、成交日、确认日和净值日期另行记录，不能从目录日期推断。

test_run_id是单测批次标识；该批次内可以有多个invocation_id，每次调用再有最多三个attempt。所有单测输入、独立数据库、运行产物、报告和辅助文件必须处于~/.investment/test/内，不能使用AppData或系统默认临时目录，不能进入正式data/runs。单测复用实际流程和验证代码，使用自己的根与历史账本，不连接正式账户库。

路径采用强校验，令P=resolve(~/.investment)、T=P/test、R=resolve(--root)：

| 运行类型 | 根路径条件 | 输入来源 |
|---|---|---|
| 正式运行 | R=P | 按所属子链正式来源契约核对 |
| 单测 | R是T的严格后代，R不能等于T | 模拟来源须保留标记，不得升格正式事实 |

SC01 的 --fixture-mode、user_confirmation/synthetic_fixture 绑定及写库阶段检查见 [SC01 T04](spec/v1/sc01.md#确定性规则)；SC02 的 mode/network_origin、插件根及输入路径约束见 [SC02 规范](spec/v1/sc02.md#存储与运行对象约束)。

单测批次根由脚本在T下新建独立目录；解析实际路径，不能用路径穿越或符号链接将测试根指向正式根。根及模式在读取输入、创建锁、运行目录或打开数据库之前检查；需要持久化业务数据的子链在写入许可及提交边界还须核对来源与根类型。错误根作为启动拒绝返回退出码2，不生成伪造业务输出或校验凭证。--root仅用于传递合法根，不能绕过这些条件。

单次调用内按 attempt-01、attempt-02、attempt-03 隔离尝试，首次加两次重试最多三次；只创建实际发生的尝试。SC01 文件、manifest 字段和路径约束见 [规则与流程](spec/v1/sc01.md)。内部目录不改变子链外部输入输出。

### 9.2. 每日 README 的位置与职责

每个子链的日期目录必须有：

~~~text
~/.investment/runs/<子链标识>/<执行日期YYYYMMDD>/README.md
~~~

该 README 与 invocation_id 目录同级，用于让读者知道当天每次调用处理什么、目录里的主要文件是什么以及是否还需要保留。

每日 README 按同目录 manifest.json 的固定字段与模板生成，逐项说明：

| 内容 | 要求 |
|---|---|
| invocation_id | 与对应执行目录、实际调用身份一致，每次调用一条记录 |
| 执行内容 | 本次处理的对象或范围、目的及内容摘要，能区分同日不同调用 |
| 主要文件及用途 | 已生成文件相对于日期目录的位置，以及各文件保存的内容；未生成时如实说明 |
| 执行状态 | 依据实际 ExecutionRecord 填写 pending、running、completed 或 failed；失败时附简短原因 |
| 保留与清理条件 | 哪些内容本轮用完可清理，哪些仍有后续用途，以及相应结束条件 |

说明只记录概要、位置和用途，完整业务数据留在对应文件或必要数据库记录中。它是人工阅读的说明，不替代 JSON 交接包或独立验收；completed 只表示处理结束，不表示业务资格通过。每日 README 不另行落库，也不成为新的永久运行历史。

### 9.3. 每日 README 内容模板

下面是填写模板，所有占位内容必须由真实调用情况替换，不能作为已经发生的执行记录。

~~~markdown
# <子链标识>：<YYYYMMDD> 执行说明

执行日期：<YYYYMMDD>
时区：<本次登记时区>

| invocation_id | 执行内容 | 主要文件及用途 | 执行状态 | 保留与清理条件 |
|---|---|---|---|---|
| <调用标识> | <处理对象/范围、目的和内容摘要> | <调用标识>/<实际文件名>：<内容及用途；未生成则说明> | <实际状态；失败原因如有> | <仍需使用的内容及用途结束条件> |
~~~

实际文件位置使用相对于当前日期目录的路径。无需统一规定所有子链都必须生成相同文件；README 必须解释实际存在的主要内容。

### 9.4. 登记与更新约束

1. 创建某次调用的执行目录时，在当天 README 登记它的身份、内容和实际状态。
2. 执行结束或发生失败后，更新同一条记录，补充实际文件、结果概要、失败原因及保留条件。
3. 同日多次调用逐项登记；更新本次记录不能覆盖或丢失其他调用的说明。
4. 尚未执行或尚未完成的内容不得写成已完成；文件尚未生成时不得写成已经存在。
5. 说明文件可随真实执行情况更新，其状态不作为下游取得业务许可的依据。

### 9.5. 必要数据与清理约束

持久化以明确的后续用途为依据，不因为某项数据曾经使用过就永久保存。

- SC01的data只保留逐笔必要买卖事实和一行当前账本元数据，登记持仓与未完成清单在runs派生；不记录余额、本金或资金来源。其他子链仅保存已明确需要跨日使用的业务数据。
- 临时输入副本、解析文本、转换结果和核对中间表等，在本轮处理与必要验收结束且没有后续依赖时可以清理。
- 未完成任务、跨日订单核对或其他有效用途仍需要的内容，保留到用途结束，不按日期直接清空。
- 清理前完成必要业务数据的持久化，并确认持续使用的数据没有仅指向待删除文件的引用；不得用新文件冒充旧版本。
- 清理调用目录时，同步移除每日 README 中对应条目，或明确标为已清理；不能留下看似仍可读取的有效文件位置。
- 清理能力按已实现子链的规范启用；SC01 的 S01/S02 与已清理标记见 [SC01 规范](spec/v1/sc01.md#必要数据存储)，SC02 当前不提供自动清理接口。

过期材料清理后，不再承诺能够完整重放依赖这些材料的历史过程。当前有效用途所需的准确引用仍须可读。
