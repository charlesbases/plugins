# SC02 v1：来源采集契约与独立验收

本规范落实 [SC02 外部责任](../../chains/news_collection/README.md) 和 [内部流程](../../chains/news_collection/internal.md)。机器权威为 [sc02.schema.json](sc02.schema.json)、[registry-sc02.json](registry-sc02.json)、[method-sc02.json](method-sc02.json)。本文的规则编号为 N01—N12。本页定义精确格式和确定性关系；实现组织、命令、场景验证及来源能力见内部说明。

## 公共输入及身份

使用既有 `investment.stage_input` → `investment.candidate_output` → `investment.validation_receipt` → `investment.sealed_output`，不增加平行外壳。`stage_id=SC02`，`contract_version/schema_version=1`；验证器为 `sc02-validator-v1`。生产者只产生候选，不能签验收凭证或封存许可。

StageInput 的 `input_refs` 必须按下表顺序，恰好五项。每项均为公共 ArtifactRef。

| role | schema_id | 对象及关系 |
|---|---|---|
| decision_clock_ref | investment.decision_clock | `clock_id,decision_at,information_cutoff_at`；两个时刻逐字等于外壳时刻 |
| news_window_ref | investment.news_window | `window_id,start_at,end_at`；`start<end<=cutoff<=decision` |
| source_scope_ref | investment.source_scope | `scope_id,entries`；外壳 scope_ref 逐字段相等 |
| query_protocol_ref | investment.query_protocol | `protocol_id,discovery_policy,limits`；策略固定 configured_entries |
| account_risk_objects_ref | investment.transaction_context | 本轮 SC01 已封存的 Context，保持原引用及字节 |

前四项、parameters_ref 和输入副本均冻结在本 invocation 的目录。账户引用必须指向 `investment-run://sc01/<date>/<inv>/attempt-0N/context.json`。验证器只检查同 run_id 的 SC01 日期 manifest、完成状态、selected sealed 引用、CandidateOutput.payload_ref 与独立凭证的身份和使用许可，不重新执行账户业务归并，不改写上游事实，也不从基金代码推导地区、行业或公司。SC01 `source_authority=synthetic_fixture` 只能用于本批测试根；正式根必须承接正式来源。

SourceScope.entries 按 source_id 字典序；source_id 为可扩展 PathID，不是封闭站点枚举。每个条目恰含 `source_id,entrypoints,material_kinds`。来源唯一、入口和类别数组无重复。类别为 article、official_release、regulatory_filing、event_record；未知来源仍在 scope、profile 绑定和 coverage 中，不能删除。配置范围并不要求全球采集。

`investment.sc02_parameters` 恰含 `parameter_set_id,mode,network_origin,plugins_dir,user_agent`。mode 为 formal/test；network_origin 为 live/simulated。simulated 只允许测试根，其原始捕获 origin 为 synthetic；live 捕获 origin 为 live。plugins_dir 为解析后的正常可配置插件目录，默认 `src/investment/chains/news/sources`。正式模式禁止读取 `.investment/test` 内插件；测试可使用打包目录，或复制/建立在本批根内的插件目录。其规则是启动时选定的受信安装文件，不能用候选提供的任意 selector 替换。

## 基础值、空值与确定性

所有结构对象必填全部声明字段，`additionalProperties=false`。Schema 是全字段、枚举、范围和可空性的完整索引。只有 Header、原始正文字符串等来源内容保留其实际值；不存在任意业务对象扩展口。JSON 为公共 canonical UTF-8 编码：键排序、无多余空白、禁止重复键、浮点 token、非有限数及超安全整数。JSON 原生数据中的小数保存在原始捕获和完整原生正文字符串内，不改造成新闻句子。

OptionalValue 使用 `{status,value,reason}`：known 的 value 非 null、reason 为空串；unknown/not_applicable 的 value 为 null、reason 非空。未知不等于零、空字符串、空集合或不适用。unknown 源时间绝不补系统时刻或猜时区。空 rows 只说明本次表中没有已确认成员，完整空窗口还需 N10 的独立证明。源标题缺失或正文定位失败不能生成 DocumentRow。

所有 Instant 为带 offset 的 RFC3339，最多六位小数；系统记录实际 UTC 时刻。TimeEvidence 的 known.value 恰为 `lower_bound,upper_bound,precision,timezone,basis_ref`；保留 instant/date/month/quarter/year/interval 的意义。正文的 source_time 保存原字面值；没有来源 offset 或规则支持的时区时，时间证据仍为 unknown。不会因显示规范化而声称来源有更高时间分辨率。published_time 与 window_time 是不同责任：USGS event occurrence 不是新闻发布时间，SEC periodOfReport 也不是 filing accepted。

单位：timeout_ms 为毫秒；response_byte_limit/decoded_byte_limit 和 byte_size 为字节；page/document/request/redirect budget、sequence_no 与 row_count 为计数；时间为带 offset 的时刻；其他引用、标识、枚举或文本的单位见表 registry。Limits 全部有限：global concurrency 1—64，per-source 1—16 且不超过 global；timeout 1—300000ms；encoded response 上限 16MiB、decoded 上限 32MiB；request 1—100000、page/document 1—10000、redirect 0—10。资源限制只控制工程开销，不是覆盖证明。

计数包含实际失败及重定向请求。purpose=document，或 purpose=data 且命中冻结 profile.document_rules 的 URL，计入 document_budget；其余 entry/listing/data 计入 page_budget。原生事件/披露材料不能通过选择 data 目的来绕过文档预算；全请求仍受 request_budget 和并发限制。

确定性标识记 `H(x)=sha256(canonical(x))`：`batch-` 加 H([run_id,invocation_id,attempt_no]) 前40位；每源 request_id 为 `req-` 加 H([run_id,invocation_id,attempt_no,source_id]) 前40位。opportunity_id 为 `opp-` 加 H([source_id,normalized_url]) 前40位；document_id 为 `doc-` 加 H([publisher_id,normalized_final_url]) 前40位；version_id 为 `ver-` 加解 Content-Encoding 后完整实体的 SHA256。corpus_id 为 `corpus-` 加本轮 input_ref.sha256 前32位；pending_id 为 `pending-` 加 H([opportunity_id]) 前40位。

URL 身份只去 fragment、规范 scheme/host 大小写及空路径 `/`，保留有意义的路径大小写、查询参数顺序、重复参数和空参数。不按同标题合并，不把不同 publisher 的材料变成独立佐证。相同 publisher/final URL/原文字节版本多次捕获保留全部请求，DocumentRow 以最早 capture sequence 为主；其他已发现 URL 经实际重定向取得相同版本时 disposition=duplicate_version。后续不同字节形成新 version。

## 统一采集接口与受信职责

`protocol.py` 定义 TypedDict、枚举和泛型 OptionalValue，接口为：

```python
async collect(request: CollectorRequest, context: CollectorContext) -> CollectorResult
async context.fetch(url: str, *, purpose: FetchPurpose,
                    parent_capture_id: str | None = None) -> CapturedResponse
async context.emit_body(body: BodyArtifact) -> ArtifactRef
context.frozen_source: FrozenSourceConfig  # 只读属性
```

CollectorRequest 恰含 `request_id,source_id,entrypoints,window,information_cutoff_at,limits`。FetchPurpose 为 entry/listing/document/data。CapturedResponse 是冻结对象，含 `capture_ref,envelope,encoded_bytes`。Context 负责全局/每源并发与预算、真实请求记录、捕获及正文落盘；每次已发请求即使超时、重定向、HTTP 错误或取消也须形成记录。插件不能制造历史、覆盖原始响应或签验证结果。每个重定向 hop 单独调用和登记，避免 HTTP 库自动跟随后遗漏历史。

受信 Context 构造时以当前 `request.source_id` 调用 `NewsResolver.source_config(input_ref,run_id,invocation_id,source_id)`，从本调用 `profile_bindings` 取得已冻结 manifest/profile。解析器核对 ArtifactRef 的类型/版本、hash/size、规范字节、当前 invocation/source 身份和已选安装规则；`investment.collector_config` 强格式表达 source_id、两项引用及对应 manifest/profile 对象。只读 `context.frozen_source` 提供同 source_id 的 FrozenSourceConfig：`manifest_json/profile_json` 为不可变 canonical bytes，`manifest_ref/profile_ref` 每次返回独立字典副本。调用方修改引用副本或自己解码后的字典不能改变受信内部绑定。插件据此读取固定规则、以 `frozen_source.profile_ref` 构造 BodyArtifact，无需猜URI或导入validator业务解析；emit_body仍核对 Context 内部原绑定。配置不含开发样本路径或单测统计，不增加 CollectorRequest/Result/Corpus 字段。

CollectorResult 恰含 `request_id,source_id,status,documents,opportunities,pending_items,coverage,errors`。status 为 completed/partial/failed/unsupported，必须与 coverage.status 一致；各行 source_id、request_id 必须属于当前请求，errors 与 coverage.errors 一致。completed 要求整窗有证、目录耗尽且无待处理/错误；partial 有有效材料但存在缺口；failed 没有有效材料且不能证明空窗；unsupported 表示没有已安装的来源规则。已安装规则访问/布局未解决是实际缺口，不冒充 unsupported 成功。所有结果均保留原配置域。

Manifest 恰含来源/publisher 身份、入口、允许 host、材料类别、interface/plugin 版本、collect.py/collect、profile SHA256、校准状态、evidence 和 limitations。`calibrated` 只表示保存样本支持解析规则，不声称 collector 已实现、运行成功或窗口完整。Evidence 仅保留原 URL、实际时刻、HTTP 状态、捕获状态、原字节 SHA/大小、角色及观察。开发样本路径仅在任务报告；正式流程不会读取开发测试样本。

ExtractionProfile 固定 charset、normalization、entry_follow_rules、listing_rules、document_rules 与 whole_window_proof。HTML XPath、XML XPath、JSON Pointer、真实页面中 API 配置的 regex 各有明确类型；不执行网页脚本。分页只遵循实际已校准链接/规则，未知机制保留 unknown，不臆造端点。正文必须命中固定 profile 的标题、正文及可选时间定位；未知布局保存 raw 和机会 pending_parse，目录未知只保留 source coverage gap，不捏造文章 ID。验证器不会读候选任意 selector，也不调用生产者业务解析算法。

## 原始捕获、正文及表

Capture 为 JSON envelope，完整字段见 Capture 定义：capture_id、request_id、source_id、全局连续 sequence_no、Optional parent_capture_id、purpose、GET、requested/final URL、request/response Header 数组、Optional HTTP 状态和 redirect_target、真实开始/结束时间、complete/partial/failed、live/synthetic、response_bytes_base64、SHA256、byte_size、Optional error。

response_bytes 是 HTTPX `iter_raw/aiter_raw` 的实体字节：HTTP transfer framing 已移除，Content-Encoding 尚未解码。它不是 TCP/TLS 或 chunk framing 的逐线抓包。Header name/value 使用原始 header bytes 的 Latin-1 可逆映射，保留重复项与顺序；正文不得先取 `.text/.content` 后冒称原始压缩字节。Base64 必须规范且 digest/size 精确匹配。complete 表示实体接收完整，不代表 HTTP2xx；HTTP403/503 的完整错误响应同样保留。partial/failed 必须有结构化 error。redirect_parent 指向同源、更早序号的真实 hop，target 与其 Location 一致。

独立解码只支持 identity/gzip/deflate，受 decoded limit 约束；解压缺尾、串接实体、未知编码或 charset 无法严格解码均不猜文本。HTML 删除 script/style/noscript，再将固定选中节点的 itertext 以空格连接、折叠 Unicode 空白；不改数字、大小写或语句。XML 用禁网、禁实体解析并以 C14N 保留原生结构；JSON detail 正文是严格解码后的完整源记录字符串，原始小数及原生数据格式不改成散文。BodyArtifact 必须逐字段等于验证器从本轮 raw 和冻结 profile 的独立提取，含 source_id、capture_ref、profile_ref、format、title、text、source_time、三种 locator 与 native_media_type。`format=json_record` 时 body_locator 必须且仅为 JSON Pointer 空字符串，指向整个原生记录；HTML/XML 必须为非空定位表达式，不能借JSON根规则放宽。这与 [RFC6901 §5](https://www.rfc-editor.org/rfc/rfc6901#section-5) 的空根定义一致。

EvidenceCorpus 恰含 `corpus_id,window_ref,source_scope_ref,documents_ref,retrieval_attempts_ref,opportunity_inventory_ref,pending_items_ref,extraction_spec_ref,coverage_ref`。Candidate.datasets 按此后六项顺序逐字段绑定；Candidate.evidence_refs 为 `[capture_log_ref] + capture_log.captures`，不能只选择成功请求。表的 DatasetRef 使用 SC02 registry，SC01 公共 dataset helper 保持原样。

| schema_id | 主键/顺序 | 核心行关系 |
|---|---|---|
| investment.news_documents | document_id,version_id | raw/body/profile 必须属于本轮，source/publisher/URL/标题/时间逐字段有据 |
| investment.news_retrieval_attempts | capture_id | 与受信 frozen CaptureLog 的全部 captures 一一相等，sequence_no 连续 |
| investment.news_opportunity_inventory | opportunity_id | 固定规则从本轮目录响应独立枚举，所有发现定位保留 |
| investment.news_pending_items | pending_id | 仅且全部未完成 opportunity 的补集，引用现存 opportunity_id/source_id |
| investment.news_extraction_spec | source_id | 恰好覆盖 source_scope 与 invocation.profile_bindings；安装/冻结字节相同 |
| investment.news_coverage | source_id | 恰好覆盖配置源，重算捕获/机会/文档/pending/错误集合 |

每表为 `{rows:[...]}`；主键唯一，按 registry.order_by 字典序。集合型 ID 数组排序且唯一；discovered_in 按 capture URI、locator 排序去重。registry.units/null_policy 与真实 row_count 精确相等。DocumentRow 除外部要求字段外，还含 source_id、title、material_kind、window_time/window_time_role/window_membership。已知 instant 只有 `start<=t<end` 才在窗内；日期/区间整个落在窗口内才 within，整体在外为 outside，不确定重叠或未知时为 uncertain。outside 不进入 documents。available_time 只有本次实际响应结束不晚于 cutoff 时才能以该实际观察时刻为保守上界；后抓取保留 retrieved_at，并以 unknown/no_availability_by_cutoff 限制历史用途，不倒推早前可得。

发布时间选择固定如下：只有 listing_rules.time_role=published 的实际字段可参与。RSS 的 item/pubDate 按 [RSS2.0 发布时间定义](https://www.rssboard.org/rss-specification) 读取，仅接受值中实际 GMT/UT/UTC 或数值offset；OData 的外层发布字段只接受实际 RFC3339 offset/Z。保留原字面值、精度及捕获引用，比较时规范化UTC，不补来源时区。候选证据按 source_id 与完整规范URL绑定；只可沿本轮已记录、同源且时间顺序有效的redirect链关联。标题相似、其他来源、WHO嵌套EmergencyEvent时间或候选自己声称的时点均不能代替绑定。

正文 source_time 原文不变。正文已支持的发布时间界限与准确绑定的列表证据合并后，选择包含于其他支持界限内的最窄已有界限，平局按正文优先、捕获顺序/条目顺序；不编造交集。冲突或不存在共同支持的已有界限时 published_time/window_time 为 unknown/conflicting_publication_evidence，并有 N07 window_time Gap，不能选恰好落在窗口内的时间。已知窗外材料须 excluded_outside_window，不能改成uncertain采用。USGS event_occurrence 与SEC periodOfReport仍不成为发布时间。发布时间证据只决定该材料的发布/窗口字段，不把 available_time 倒推为早于真实观察的时刻。

Opportunity disposition 互斥：captured、excluded_outside_window、excluded_kind、duplicate_version、pending_fetch、pending_parse、failed_fetch。排除必须有实际源时间或冻结材料类别依据；没有时间不能排除为窗外。前三种 pending/failed 构成 pending 表的精确集合：pending_parse 要 supported_layout，其余要 source_response，affected_uses 固定三个研究用途。未访问范围只在 coverage/gap 表达，不能伪造文章清单。文档必须属于从配置入口经真实发现、分页、API 跟随或重定向可达的请求图。

## 覆盖、规则及许可

CoverageRow.listing_state 分为 exhausted_exposed、verified_window_boundary、budget_stop、error、unknown。已耗尽暴露列表不等于整窗完整；RSS/latestN、成功请求数及达到预算都不能证明历史窗口。whole_window_proof 默认 unknown。扩展规则只有在受信 profile 中冻结显式 bounded catalogue 规则，并从本轮真实响应重读其完整标记、起止界、确认覆盖输入窗口、所有已暴露链接已处置且无错误/pending 时，才能 window_coverage=complete。打包来源的当前能力见 [内部说明](../../chains/news_collection/internal.md#来源能力与限制)。

| 规则 | 独立检查 |
|---|---|
| N01 | 封闭 Schema、注册项、根/模式/入口命名空间 |
| N02 | 所有实际引用、SHA/大小、表元数据、主键/顺序及 Corpus 绑定 |
| N03 | 五角色/时钟/范围/当前尝试、SC01 交接、固定方法及受信安装/冻结 profile |
| N04 | 全请求账本、source/request/原字节/redirect/生命周期/网络来源 |
| N05 | 全局和每源实际并发、总超时、字节、页/文档/请求/redirect 预算 |
| N06 | 固定规则独立重提正文/标题/原生记录/定位，拒绝 parser/copy 错误 |
| N07 | 文档身份、版本、源时间精度、窗口及 cutoff 可得性 |
| N08 | 配置入口可达性、全部发现机会、真实排除/去重/采用/失败处置 |
| N09 | pending 精确补集与外键 |
| N10 | 每个配置来源、真实覆盖/未知范围/预算/错误及集合 |
| N11 | 至少一个有效材料，或全部来源都有可核空窗证明 |
| N12 | 完整、确定排序的 Gap 与候选外壳绑定；研究用途限制 |

凭证列出全部 N01—N12；前提失败后的检查明确 not_evaluated。结构/关系/事实不支持时 rejected、无用途；没有有效材料且没有有据空窗时 blocked、无用途。有效部分材料允许 observation_only，overall_verdict=partial；保存缺口，仅允许 evidence_review、hypothesis_research、reporting。所有来源失败不能放行。完整且时间有据的 live 材料最多 usable，仍只有这三个用途。synthetic 永远 observation_only，不能得到正式投资、decision_advice、pit_training 等许可。partial 通过完整性验收不表示完整目标 achieved；runtime 的 goal_status 另从整窗/缺口/来源事实确定。

Gap 精确生成：每个未知整窗来源 N10 `/coverage/<source_id>`；每个 uncertain 文档 N07 `/documents/<id>/window_time`；每个 cutoff 可得未知文档 N07 `/documents/<id>/available_time`。固定 owner=source、required_evidence=[source_bytes]、affected_uses=上述三项，具体 reason 见实现和 method。候选不能删除这些缺口。

## 存储与运行对象约束

正式根固定 `~/.investment`；测试根是其 test 的严格后代。根、模式、插件根和两个输入路径必须在读取任意输入、创建目录/锁、打开数据库前强校验。SC02 不新增数据库，也不增加顶层运行目录。

```text
runs/sc02/<YYYYMMDD>/
  manifest.json
  README.md                    # 与 invocation 同级，由真实 manifest 生成
  <invocation_id>/
    input.json                 # 冻结公共 StageInput
    parameters.json            # 固定参数
    clock.json window.json scope.json query.json
    plugin-<source_id>.json profile-<source_id>.json
    attempt-01/                # 首次加两次重试，最多 attempt-03
      capture-<capture_id>.json
      capture-log.json          # Context 所有实际请求，冻结后供独立验证
      body-<capture_id>.json
      documents.json retrieval_attempts.json opportunity_inventory.json
      pending_items.json extraction_spec.json coverage.json corpus.json
      candidate.json receipt.json sealed.json failure.json
```

NewsResolver 只读 SC02 规范文件与精确 run grammar；日期必须真实、invocation 为 PathID、attempt 只能 01—03、JSON 文件名禁止目录穿越/query/fragment。SC01 引用仍走原 Resolver。spec locator 为 `investment-spec://v1/registry-sc02.json` 和 `investment-spec://v1/method-sc02.json`。原始网站 URL 的 query 属于来源内容，不能与 artifact URI 禁 query 混淆。

DailyManifest/Invocation/Attempt/Failure/FailureSummary/RunResult/UnitReport 有独立强类型。Invocation 在发请求前持久化冻结输入、方法、参数、profile_bindings 和本次 attempt；attempt_no 从既有清单追加，跨中断不重置，最多3次。CaptureLog 记录本次受信 Context 的完整请求引用，在验收前冻结；candidate_ref 同样由控制侧冻结。失败必须存实际 phase/rule/code/pointer/evidence 和 retryable，不造正常输出。三次耗尽 failure summary 明确 downstream_allowed=false。相同已完成 invocation 返回原封存控制结果；新 invocation 重新联网，不以既往产物或测试报告替代当前执行。只有独立凭证合格后控制器才能写 SealedOutput；处理完成、证据有效和目标满足分别表达。持久化生命周期及每日 README 服从项目存储规则。

运行对象关系约束：attempt_no 必须连续等于1到当前数组长度，校验只接受最后一次当前尝试；前次失败记录与已用预算不能消失。running 的 finished_at 为 unknown，结束后才 known；failed attempt 有 known failure_ref，成功完成有 known receipt_ref/candidate_ref。Invocation.completed 必须有同身份的 known sealed_output_ref 与实际 finished_at；Invocation.failed 必须有 known failure_summary_ref，不能同时有正常 sealed_output_ref。FailureSummary.attempt_count、attempt_failure_refs 长度和实际失败次数相等，所有引用的 run/invocation/attempt 身份相符。RunResult 的 sealed/failed 分别只携带对应结果的 known 引用，另一项 not_applicable；goal_status=achieved 还要求所有配置源整窗完整、无未解决资格缺口且为live，模拟或部分覆盖为unmet。UnitReport 不成为业务 Corpus；execution_succeeded/output_valid/goal_satisfied 分别据实际执行、独立验收与原目标判断。

UnitCase 的 input_ref、candidate_ref、receipt_ref 均为必填 OptionalRef，字段名不变，每项恰含 status/value/reason：

- known：reason 必须为空串；value 必须是本次 case 实际已产出的完整 ArtifactRef，分别绑定 investment.stage_input、investment.candidate_output、investment.validation_receipt，media_type 为 application/json、schema_version 为1、byte_size 为正整数字节数。必须在该 case 声明的本轮根内读取对应真实文件并核对身份、类型、canonical bytes、SHA256、长度及依赖关系；仅通过 Schema 不能证明引用存在或业务有效，禁止以占位 URI、零长度文件或伪造摘要替代产物。
- not_applicable：value 必须为 null；input_ref.reason 只能是 input_not_created，candidate_ref.reason 只能是 candidate_not_produced，receipt_ref.reason 只能是 validation_not_run，表示有实际执行证据的未创建、未产出、未运行。已运行但拒绝的真实凭证应使用 known，不得改报 validation_not_run。
- unknown：value 必须为 null，reason 为非空的具体证据缺口，不能使用上述三种已证缺失码；不能把不知道引用状态解释为已经证明没有产物。

Schema 强制两个 UnitReport.allOf 必要条件：output_valid=true 要求每个 case 的三个引用 status 全为 known；goal_satisfied=true 要求 execution_succeeded=true 且 output_valid=true。因此任一 case 的任一引用是 unknown 或 not_applicable，output_valid 与 goal_satisfied 都必须为 false。全部 known 只是必要条件；output_valid=true 还须本轮实际独立业务验收合格，goal_satisfied=true 还须实际满足原目标，不能由引用齐全或 passed 推导。execution_succeeded 只依据实际执行结果，不因测试预期成立而改真。

passed 只表示该 case 的实际结果符合其独立预期，允许正确拒绝的 case passed=true：三次失败没有候选/未运行验收时可有 known input、candidate_not_produced、validation_not_run；入口隔离拒绝在输入未创建时三项可依次为 input_not_created、candidate_not_produced、validation_not_run。两种情形的 execution_succeeded/output_valid/goal_satisfied 均为 false，不能冒充业务输出成功。格式校准不等于执行上述业务场景，实际 all_failed/isolation 仍由其原批准 selector 产生证据。

## 验证入口结果

正式模式使用 `--mode formal --network-origin live`，plugins-dir 可省略。stdout 仅 canonical 公共 ValidationReceipt；有研究用途退出0，rejected/blocked 退出1；启动命名空间/文件拒绝退出2且不伪造凭证。验证器不写候选、不联网、不自动打开文件。
