# SC04：投资工具范围与暴露映射内部设计

文档版本：v1。状态：内部实现规划，待实现与验收。

[外部契约](README.md) · [公共规则](../../contracts.md) · [总体规则](../../architecture.md)

本页规划主动目录发现、完整同类列表搜索、身份及暴露取材、逐成员处置和范围封存。范围必须先于结果选择冻结，当前研究与历史范围分别记录。内部步骤形成私有结果，不能授予对外业务许可。

## 步骤与私有结果

1. **登记发现计划。** 接收账户、研究评审、universe_discovery_spec_ref、准入和暴露规则及时点请求，展开待研究假说、暴露和需要比较的持仓产品。登记适配器、分析器、方法版本、完整性判据及预算。目录和身份资料可以复用，复用先核对准确来源、时点和支持范围；不要求调用者预填原始资料。
2. **主动发现目录与同类列表。** 通过目录和列表 Provider 取得原始响应，展开来源支持的分页、游标、查询及后续链接。任务保存原请求、来源身份和父子关系，每次实际请求形成尝试记录。搜索面向声明渠道和产品域的完整同类列表，不接受手选代码、白名单、top N 或按表现筛选成员。未处理的分页和来源范围保留为补集。
3. **取得身份与暴露原文。** 从原目录、列表和真实来源链接取得法律基金、份额类别、基准、跟踪目标和披露材料，保存字节、定位、出版及获取时点。名称或关键词只产生取材任务；未知身份保留 member_id 与原条目定位，不捏造代码。冲突、未知布局和未取得材料形成补核任务。
4. **核验同类归属。** 按冻结规则核对身份、基准主体与目标、资产类别、币种及策略口径，将假说关联到可核暴露，保留披露版本、权重或范围及可得时间。归属未知的可能成员继续保留；不以缺字段为由缩小分母，不以名称相似性替代可比证据。
5. **冻结原始名单并逐项处置。** 汇总原列表及成员来源关系，将发现名单与闭合结论分别保存，再按指定时点的准入规则形成 C、E、K。每项排除保留规则及来源；没有 NAV、费用或模型样本不能自动变成范围排除。逐成员处置完整覆盖 U，后续资料资格不能倒改原名单。闭合未核实的名单仍可封存为限定观察，不能认证完整。
6. **重建历史范围。** 对每个请求 origin 使用当时可得的目录、身份、暴露和准入版本，保留后来消失的对象。缺历史或可得性证据形成 Gap，不能用当前成员填补，也不能把今天取得的旧资料改成过去已知。
7. **汇总并提交验收。** 核对原列表、可能成员、补集、分区和身份关系，另行汇总持仓、现金和在途风险。组装 InstrumentUniverse、DiscoveryAudit、覆盖说明及 CandidateOutput，交主调度独立验证与封存。

发现任务、原列表索引、身份关系、暴露草稿、同类归属和准入判定均为私有结果，保留准确输入、方法、来源和失败原因，不直接成为下游许可。风险清单中的对象即使资料未核也须保留，不能因此冒充合格候选或训练成员。

## 完整性与资料处置

原列表保存来源声明、原始字节、页码或游标、查询边界、实际完成情况及成员映射。闭合需要核查来源的覆盖域和列表含义、分页是否结束，以及可能同类和未解析条目是否得到处置。只读部分页面、取得若干代码或完成一个批次，不能认证完整。单一发行人的列表闭合不证明跨发行人的同类列表完整。

已发现的可能成员进入未知处置；尚未展开的列表区间或来源域进入未处理范围。不为未知范围捏造代码，不通过删除失败任务、未解析条目或可能成员制造闭合。明确不适用的任务保留规则和来源依据。

SC04 判断身份、暴露和范围准入；NAV、权益、费用、申赎、锁定、到账和日历的完整取材由 SC05 负责。SC05 发现身份或原分母冲突时交回主调度处理受影响的 SC04 结果，不能在下游静默缩小成员集合。

## 组件扩展、并发与恢复

目录发现、分页捕获、身份和披露取材使用各自 Provider 能力接口；身份核验、准入、暴露映射和同类判定使用各自 Analyzer 约定。注册项记录实现、方法、支持来源域及私有类型版本。网站字段由适配器转换，新增同能力组件不将私有字段或名称加入 InstrumentUniverse。

独立来源和不同基金取材可并发，统一汇总处理分页依赖、身份冲突、重复成员和分组一致性。站点及全局预算统一记账，失败和重试不删除；一个来源成功不能填补另一个来源的缺口。部分失败时保留受影响成员、暴露、未知范围及 Gap，不补零权重、不删除风险对象，不以分析器投票代替合同证据。

恢复沿用冻结计划、来源版本、已完成任务和累计尝试，继续未处理范围。新来源或规则变化形成新绑定，不能替换原输入而沿用旧闭合结论。

## 输出与边界

当前与历史范围分别组装；未请求历史范围表达不适用，请求但未能支持则表达未知和 Gap。无法取得必要原列表时保存真实失败，不补造正常 payload，不把未知写成无成员。

生产者仅输出 CandidateOutput。独立验证者重读原始目录、列表和身份材料，检查闭合、逐项处置、分区、时点与风险保留后签发 ValidationReceipt，调度者封存。完整性未知限制完整同类比较；内部排名不能在此授予最佳基金、预测或可买资格。

SC01只提供基金交易、确认份额、未完成交易和到账状态；资金计划与用户风险/期限/流动性约束由任务材料独立绑定，不从买卖差额反推余额、净资产或本金。缺少这些独立材料时限制依赖它们的结论，不反向阻止合法交易登记。
