# SC09 内部流程：建议映射与发布核对

文档版本：v1。状态：内部设计，待实现与验收。

[对外契约](README.md) · [公共契约](../../contracts.md) · [总体设计](../../architecture.md)

本页定义子链私有编排。对外字段与含义以 README 为准；私有检查结果不能替代独立许可，不能改变封存动作、金额、排名或资格。

## 步骤与私有结果

1. **绑定输入。** 核对政策、资格、当前动作和账户的准确引用、哈希、许可范围及有效期间。形成输入绑定表，记录每项动作的原始身份与祖先关系；对象错配立即停止。
2. **检查发布条件。** 将发布时账户核对、行情可得性、费用合同、申赎状态和提交窗口逐项对照冻结前提。形成条件矩阵，保存证据、时间边界和未知原因；新资料只用于核对，不能替换原决策输入。
3. **确定性映射。** 按原动作形成申购实付金额或赎回份额，保留是否含费、批次分配和执行条件。逐项生成持仓及候选处置说明；no_action 引用验证依据，risk_recovery 核对单独政策许可。映射结果保留原动作与建议行对应关系。
4. **核对精度。** 用精确十进制检查金额步长、份额步长、舍入规则与映射前后数值及经济效果。发现不合法精度时返回责任阶段，不在发布环节改金额或重新求解。预测份额、费用和到账估计保留假设、时点及证据。
5. **组装候选。** 将映射表、处置说明、资金条件、发布核对和限制装入既有 RecommendationSet。未知值与不适用值按公共类型表达；必要条件的最早有效边界决定 valid_until，过期对象只保留历史用途。
6. **交接验收。** 输出 CandidateOutput 和私有核对记录，由独立验证者检查、调度者封存。封存前核对仍有效的发布前提；生产者不签发 ValidationReceipt，也不据内部成功标记开放下游。

## 并发、失败与恢复

账户、市场、费用及窗口核对可并行，但共享同一冻结输入清单，分别保存结果后集中汇合。金额映射和最终组装等待全部必要检查；相互冲突的结果不能按完成先后覆盖。

证据不足时保留 Gap，候选观察结果不含交易指令；资金未到账只说明条件，到账后更新独立资金计划；涉及基金卖出时登记交易到账事实，再重算受影响方案。账户、风险、市场或合同前提变化时阻断旧建议，交回受影响阶段产生新版本。恢复仅复用输入一致、引用可核且仍有效的私有结果；保留失败与尝试记录。

内部可扩展渠道状态适配器和条件说明组件；扩展必须归入上述步骤，不新增对外字段或修改金融含义。

SC01只提供基金交易、确认份额、未完成交易和到账状态；资金计划与用户风险/期限/流动性约束由任务材料独立绑定，不从买卖差额反推余额、净资产或本金。缺少这些独立材料时限制依赖它们的结论，不反向阻止合法交易登记。
