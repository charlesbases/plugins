# 内置公开净值研究准备与独立审计

## 调用与归属

Python 3.10+，只用标准库；prepare需要HTTPS联网，status和verify无需联网。每次从**当前安装技能目录**调用scripts/research.py。不要执行数据缓存中的旧脚本。缓存中的executor副本只用于留存当时的代码与证据，日常仍执行安装版并检查代码哈希。版本号相同也不代表代码相同。

```bash
python -B <skill-dir>/scripts/research.py status --root <root> --plan <plan-id>
python -B <skill-dir>/scripts/research.py prepare --root <root> --plan <plan-id> --codes <code...> --start YYYY-MM-DD --end YYYY-MM-DD
python -B <skill-dir>/scripts/research.py verify --root <root> --plan <plan-id>
python -B <skill-dir>/scripts/research.py verify --root <root> --plan <plan-id> --run research/YYYY/MM/DD/run-id
```

参数中的占位符须换成真实值，不是可直接执行的命令。root缺省沿用storage.py的HOME规则；plan缺省沿用活动或唯一计划。多计划未选择、损坏配置或丢失活动计划报错，不重建覆盖。全新环境可建立purpose=research的稳定计划及活动指针，不能创建真实持仓、现金或成交记录。

prepare要求明确代码和历史起日，不推断个人购买列表。每次最多50个不同六位代码是工程请求预算，不是统计样本充分门槛。公开接口必须包含适配的单位/累计净值JSON和匹配的fS_code；不适配的货币基金等数据、未知分红或拆分停止，不冒充已支持产品。终日缺省为北京时间当天；自然日期限缺省30/60/90，lookback缺省120个净值区间，仅定义当前基线窗口。

## 首次与之后

1. status检查账户与研究引用。研究资料不构成持仓；已有持仓反馈和账户状态按存储规则处理。
2. 已有内置研究引用执行verify，复查当前字节、文件集合、政策、来源和执行器。旧缓存临时脚本的格式返回legacy_requires_prepare；代码更新、文件损坏或引用不兼容时保留旧资料并prepare新快照，不能直接信任旧passed字样。
3. 需要更新行情或重查待成熟标签时prepare。每个运行使用新的日期目录，不覆盖旧分片，不把失败的一半运行登记成功。同内容的semantic_fingerprint相同，不以新的获取时间伪装为新增训练观察。
4. 市场研究通过后登记manifest/audit路径及哈希。完整历史交易资料缺失仍为data_unavailable，旧模型状态和引用保留。允许以明确假设执行条件拟合及 [组合检验](allocation-method.md)，但正式投资资格必须另经完整数据及效果验收，不能把条件研究直接启用。

## 生成和核验规则

- 原始JS、网页、PDF保留下载字节、URL及获取时间，只解析JSON，不执行JS。供应商请求ID、URL和fS_code必须指向同一产品。按真实估值日期保存，包括存在的周末估值；估值日期不代表可交易日期。
- research-evidence.json保存人工审核过的官方文档摘要、文档SHA-256、份额类别、日期、单位及原文位置。下载文档与审核哈希匹配才使用这些锚点/补录；内容变化或下载失败明确排除并待重新核实。PDF格式正确本身不等于内容核验。
- 已知分红备注缺漏：按匹配官方证据生成带issuer_correction的规范化记录，保留空白原备注。数据商已补齐且金额一致时记为corroborated no-op；金额冲突停止。没有官方证据时不能单靠累计净值差推断补录。
- 单位净值、累计净值与总收益分别处理。过去窗口的特征不使用未来净值；当前经理、费用和新闻不回填历史特征。历史公开时刻未知保持空值，不能声称严格时点可得性通过。
- 市场标签使用起点单位资本1，保留起点之后的现金分红权益，不再投资、不计算现金利息、不假定实际到账；起点当天分红不算后续权益。目标为起点估值日期+h自然日，终点为其后第一个实际观察，另存偏移。管理/托管等净值内费用不重复扣。此口径不是实际申赎模拟。
- 终点负收益、本金路径损失、峰值回撤分别计算。未到期结果保持pending/空值。历史平台费率、可买性、限额、确认和到账条件缺失时，实际投资者净收益保持空值，不能把市场标签改名为交易训练标签。
- 审计独立从原始资料用Decimal复算全部净值、特征和标签，不调用生成器计算函数。完整文件集合、政策、证据及代码均纳入哈希；改动、新增、删除或重新封装错误数值都不能沿用旧成功状态。显式异常在Python优化模式下仍有效。

官方核对是有限锚点，不代表每条观察独立验证；没有已审核锚点的代码报告来源缺口。未知底层组合身份保持空值，不把A/C份额当作独立基金或据此宣称全市场模型覆盖。内置证据表不是评分器或推荐名单。

## 写入、错误与复现

新研究运行保存于所选root/plans/plan-id/research/YYYY/MM/DD/run-id。normalized、features、labels按基金及月份分片，单片最多16 MiB；清单和状态文件最多1 MiB。数据不得写入插件安装目录。账户文件与流水在发布前比对；后续合法更新持仓不会使既有市场研究失去算术资格。

每个计划的准备写入持有独占锁；遇已有锁报错，不盲目删除。资料下载单次超时可设1—30秒，单响应最多16 MiB；失败保留run-status中的阶段和原因。发布前重新复算/比对完整审计并检查索引未被其他写入者改变，索引原子替换是最后提交步骤。失败保留旧成功引用，不修改state/current.json、现金、订单或成交记录。

verify只读，不下载、不改写旧资料。默认核对登记的manifest/audit路径和哈希，再独立复算并对照完整保存审计；指定旧run时核验其自身审计。root、plan和run必须与实际所选目录一致，不能复制其他计划的运行并沿用其身份。基金身份匹配已审核注册表，清单摘要也独立重算。合法后续账户更新不使市场研究算术失效。

manifest保存冻结政策、执行器哈希、资料清单和语义指纹；audit分别报告市场算术、官方锚点覆盖、历史交易资格及模型未拟合。研究发布使用storage.update_latest的共享索引锁和预期哈希；新闻、报告和模型写入者按storage.md使用同一入口，不直接重写latest。源码升级后以新安装版prepare重新生成，不直接运行旧缓存代码。研究准备有效不等于基金收益可预测，预测有效性仍按training.md独立验收。
